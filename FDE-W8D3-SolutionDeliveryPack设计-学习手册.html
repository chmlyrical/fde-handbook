FDE W8D3 学习手册 · Solution Delivery Pack 设计

W8 Day3 · A 级（必须掌握，面试核心）· 6h · 学完能独立产出一份 15-18 页、叙事闭环、不夸大的 AI 交付方案

本日定位：前两周你做了知识库、特药理赔 Agent、企业 Agent 平台三件作品，Day3 把它们"串成一份能拿去见客户/老板的方案"。候选人有 Java + 大数据 + 医疗保险背景、冲刺架构/负责人岗——这类岗的核心产出就是"方案"。本日是面试里"方案设计/售前思维"的标准答案来源。
学完能回答：① Delivery Pack 的核心结构与叙事逻辑（痛点→方案→证据）；② 怎么把 POC 差距和成本风险写清楚、不夸大。
使用方法：先理解叙事逻辑 → 背 15-18 页清单 → 重点看"四类边界""POC 差距""成本风险"三节（最易被追问）→ 做自测 → 配合《FDE-W8D3-评测题.md》。标注（左下★重要 / 右下📌待查）用于圈出自己方案的薄弱环节。

一、什么是 Solution Delivery Pack（交付方案包）

1.1 定义

Delivery Pack 是 FDE（前端/解决方案交付工程师）向客户或内部决策层交付的一份结构化方案文档，目标是让对方在 15-18 页内看懂："你的问题是什么、我用什么 AI 能力解决、证据在哪、要花多少钱、有什么风险"。它是作品集的"汇总叙事"，不是代码。

1.2 与作品集的关系

维度作品集（三件套）Delivery Pack
形态知识库 / Agent / 平台（可运行）一份方案文档（PPT/PDF）
目的证明"我能做"证明"我懂你、能落地、值这个价"
受众技术面试官客户决策层 / 老板 / 跨职能评委
对 36 岁冲刺负责人岗的候选人，Delivery Pack 是"把技术翻译成商业价值"的能力证明。面试官看它，本质是看你有没有"方案 owner"的视角，而不是只会写代码。
Delivery Pack 是一份 15-18 页的结构化方案，把你的三个作品（知识库/Agent/平台）串成"痛点→方案→证据→成本→风险"的闭环，给决策层看。它是作品集的汇总叙事，不是代码本身。
① 别把它写成"技术说明书"——决策层不关心你用了什么注意力机制，关心"省了多少、风险多大"。② 也别写成"纯 PPT 吹牛"——没有证据和风险的方案会露馅。③ 它和简历/作品集互补：作品证明能力，Pack 证明商业理解。

二、核心叙事逻辑：痛点 → 方案 → 证据

2.1 三段式黄金结构

痛点（Why now） → 方案（What & How） → 证据（Proof）　+　成本与风险（Honesty）
  1. 痛点：现有流程卡在哪、人工成本多高、错误率多少——必须用数字。
  2. 方案：用规则/RAG/Agent/人工四类的哪一层解决哪类问题，对应你哪个作品。
  3. 证据：POC 指标、准确率、节省工时、用户反馈——可验证。
  4. 成本与风险：要花多少、POC 到生产差多远、风险怎么控——诚实。

2.2 为什么这个顺序

决策层的注意力曲线是"先认同问题，再看解法，最后才信证据"。先抛痛点建立共鸣，再给方案顺理成章，证据闭环信任，诚实的成本风险反而加分。

叙事逻辑是方案的"骨架"。架构师述职、售前投标、晋升答辩，底层都是这套"痛点-方案-证据"。能讲清这条线，你就有了负责人岗的叙事能力。
Delivery Pack 的黄金叙事是"痛点→方案→证据"，再加诚实的"成本与风险"。先让对方认同问题，再顺给解法，用证据闭环信任，诚实谈风险反而更可信。顺序不能乱。
① 痛点不量化（"效率低下"）是致命伤，必须"当前人工审单 8 分钟/单、错误率 3%"。② 证据和痛点要对得上——痛点说省人工，证据就要给工时节省数。③ 把风险藏起来是减分项，主动写清 POC 差距才显专业。

三、标准结构总览（15-18 页）

页章节核心内容
1封面与一句话价值方案名 + 给客户的核心收益（一句话）
2-3现有流程与痛点流程图 + 量化痛点（工时/错误率/合规风险）
4AI 适用性分析哪些环节适合 AI、哪些不适合
5数据准备度数据现状、缺口、治理计划
6规则·RAG·Agent·人工边界四类能力如何分工（呼应 W6-W7）
7POC 范围本期做什么、不做什么
8保险知识库（作品1）架构 + 效果指标
9特药理赔 Agent（作品2）流程 + 准确率 + 边界
10企业 Agent 平台（作品3）多租户 + 编排 + 治理
11数据和知识架构向量库/图/权限的数据流
12安全与权限鉴权、脱敏、审计、合规
13评测与 LLMOps评测集、监控、回归、迭代
14部署拓扑私有/混合、容量（呼应 W8D1/D2）
15NFR 与实测延迟/可用率/并发的实测值
16POC 到生产差距诚实列出差距与填补计划
17成本与风险估算 + 风险矩阵 + 缓解
18上线计划与里程碑分阶段路线 + 成功标准
这份清单是"满分骨架"。实际可根据客户关注点合并（如安全与权限并入数据架构），但痛点、四类边界、POC 差距、成本风险四页不能省——它们是面试官最盯的地方。
15-18 页不是越长越好，是"覆盖决策关心的所有维度且不啰嗦"。架构师要会按受众裁剪：给 CTO 侧重技术架构与风险，给业务 VP 侧重痛点与收益。
标准 Pack 是 18 页骨架：封面→痛点→AI适用性→数据→四类边界→POC范围→三个作品→数据/安全/评测架构→部署→NFR→POC差距→成本风险→上线。痛点、四类边界、POC差距、成本风险四页是必保项。
① 页数是结果不是目标，为了凑 18 页灌水会露怯。② 三类作品页（8/9/10）要"对应痛点"，不能变成孤立的产品介绍。③ 把"安全与权限"当附录是常见错误，医疗/保险合规必须前置。

四、三个作品如何串成一份方案

4.1 串法：以"场景"为主线，不以"技术"为主线

错误写法：先讲知识库技术、再讲 Agent 技术、再讲平台技术（变成三份说明书）。

正确写法：以特药理赔场景为主线——

  • 客户问条款 → 保险知识库（RAG 检索）提供准确依据；
  • 客户要审单 → 特药理赔 Agent 调用知识库+规则引擎完成初审；
  • 企业要规模化 → 企业 Agent 平台 把上面两个能力多租户化、可编排、可治理。

4.2 叙事闭环

一个业务场景 → 知识库(给知识) + Agent(做决策) + 平台(规模化/治理) = 完整价值
串讲的本质是"用一个故事把三件套变成一套能力"。负责人岗要展示的不是"我做了三个东西"，而是"这三个东西合起来解决了你一个多大的问题"。
三作品要按"场景"串联而非"技术"罗列：用特药理赔场景把知识库（给知识）、Agent（做决策）、平台（规模化治理）串成一条线，讲清"合起来解决一个大问题"，而不是变成三份孤立说明书。
① 三个作品页如果互相没引用，说明没串起来。② 平台页别只讲技术中台，要落到"让前面两个能力能被 10 个部门复用"。③ 串联时要点明每层的边界（见 s6），否则像堆砌。

五、现有流程·痛点·AI 适用性·数据准备度

5.1 痛点页（必须量化）

痛点维度示例（特药理赔）
效率人工审单 8 分钟/单，日 5000 单需 60+ 人力
质量条款引用错误率 3%，引发投诉/合规风险
合规敏感病历跨系统流转，审计难

5.2 AI 适用性

  • 适合 AI：条款检索、材料初筛、结构化抽取、常见问题应答。
  • 不适合 AI alone：最终赔付决策、法律定性——必须人工或规则兜底。

5.3 数据准备度

列出：知识库源（条款 PDF/理赔规则库）、数据质量（OCR 准确率、缺失字段）、治理计划（脱敏、标注、更新机制）。

数据准备度是方案的"地基诚实度"。面试官常追问"你的数据从哪来、干不干净"，答不出说明没真做过。医疗数据还要点明脱敏与授权。
痛点页必须量化（工时/错误率/合规风险）；AI 适用性要分清"适合 AI"和"必须人工/规则兜底"；数据准备度要诚实讲清数据来源、质量与治理，这是方案的地基。
① 痛点写"效率低下"这种定性词=不及格，必须带数字。② AI 适用性若写"全场景 AI 化"=夸大，合规/最终决策要人工。③ 数据准备度回避"数据脏"会被追问击穿，不如主动写治理计划。

六、规则·RAG·Agent·人工 四类边界设计

6.1 分层决策（呼应 W6/W7）

层负责示例
规则（Rule）确定性强、可枚举的逻辑免赔额计算、黑名单拦截
RAG知识检索与依据提供条款引用、政策问答
Agent多步编排与工具调用审单流程：检索→计算→生成结论
人工高风险最终决策/异常拒赔判定、金额超阈值

6.2 边界原则

能规则的不上 RAG；能 RAG 的不上 Agent；Agent 只编排，最终风险点必留人工
四类边界是"可控 AI"的核心。负责人岗要在方案里画一张"决策路由图"：什么情况走规则、什么走 RAG、什么走 Agent、什么必须人工。这直接体现你对风险的理解。
四类边界原则：能规则的不上 RAG（省成本稳），能 RAG 的不上 Agent（防失控），Agent 只做编排，高风险最终决策必留人工。方案里要画"决策路由图"说明每类的适用边界。
① 把所有决策都丢给 Agent 是重大风险点，面试官会追问"出错了谁负责"。② 规则和 RAG 不是替代关系，是互补（规则保证硬约束，RAG 提供软知识）。③ 人工边界要定义"触发条件"（如金额/拒赔），不能模糊说"复杂情况转人工"。

七、三件套：知识库 / 特药理赔 Agent / 企业平台

7.1 各作品页要写什么

作品页内要点对应痛点
保险知识库向量+图混合检索、条款准确率、更新机制条款引用错误率 3%
特药理赔 Agent审单流程、准确率、拒答率、人工兜底人工审单 8 分钟/单
企业 Agent 平台多租户、编排、权限、监控能力无法规模化复用

7.2 写法要点

  • 每个作品都要"回指痛点"（s4 串联的落地）。
  • 给可验证指标：准确率、召回率、P99 延迟（呼应 Day1/Day2）。
  • 给边界：这个作品不解决什么（避免夸大）。
三件套页要"各有边界、互相印证"。知识库解决"不知道"，Agent 解决"不会做"，平台解决"扩不开"。三页合起来才是一个完整能力图谱，缺任何一页故事都不闭环。
三个作品页都要"回指痛点+给可验证指标+写明边界"。知识库解决"不知道"（检索），Agent 解决"不会做"（编排决策），平台解决"扩不开"（规模化治理）——各有边界、互相印证才闭环。
① 作品页只写"我们做了 XX"不写指标=没证据。② 不写边界容易被追问"那它也能做 Y 吗"，答不上来。③ 平台页若脱离前两个作品谈"中台能力"，会显得空中楼阁。

八、数据和知识架构 + 安全与权限

8.1 数据和知识架构

  • 数据流：源数据 → 清洗/脱敏 → 向量化/图谱化 → 检索 → Agent。
  • 存储：向量库（召回）+ 关系/图库（实体关系）+ 对象存储（原文）。
  • 知识更新：条款变更如何增量更新、避免全量重建。

8.2 安全与权限（医疗合规前置）

控制项做法
鉴权网关统一鉴权，模型服务不直接暴露
数据脱敏病历/身份证在入库与推理前脱敏
最小权限租户隔离、字段级授权
审计每次推理留痕（谁、问了什么、用了哪条知识）
呼应 W8D1：私有部署 + 不出域是合规底座；呼应 W8D2：安全投入也计入 TCO。医疗方案里安全页不能后置。
安全与权限在医疗/保险是"一票否决项"。架构师要在方案里展示"数据从进入到销毁的全链路可控"，这往往比模型效果更能拿下合规型客户。
数据架构要画清"源→脱敏→向量/图→检索→Agent"的数据流与存储选型；安全页要覆盖鉴权、脱敏、最小权限、审计四件，医疗合规须前置而非当附录。
① 把安全当附录是医疗方案大忌，合规评委直接扣分。② 只说"我们有鉴权"不够，要具体到脱敏时机与审计留痕。③ 多租户隔离若只讲逻辑不讲实现（如向量库 namespace），会被质疑落地性。

九、评测与 LLMOps + 部署拓扑

9.1 评测与 LLMOps

  • 评测集：正常/边界/应拒答 case（呼应 Day9 评测体系）。
  • 监控：延迟、准确率漂移、成本（呼应 Day2）。
  • 回归：模型/知识更新后的自动回归。
  • 迭代：基于 bad case 的知识与 prompt 闭环。

9.2 部署拓扑

私有(数据不出域) + 可选 API 兜底(峰值) = 混合部署；容量按 Day2 规划、性能按 Day1 实测
LLMOps 页体现"方案能活下去"——很多 POC 很美但上线后指标漂移无人管。架构师要展示评测+监控+回归的闭环，证明你能运营而非只交付。
评测页要覆盖评测集/监控/回归/迭代闭环（呼应 Day9）；部署拓扑用"私有+API 兜底"混合，容量按 Day2、性能按 Day1。这证明方案不只是 POC 能跑，而是能运营。
① 只写"我们有评测"不写评测集构成=空话。② 部署拓扑若不考虑容量（Day2）与实测指标（Day1），会与前文矛盾。③ LLMOps 漏掉"知识更新回归"是常见坑——条款一变模型就错。

十、POC 范围与"POC 到生产差距"（不夸大）

10.1 什么叫诚实写差距

POC 是"在受控小样本上验证可行性"，生产要"在真实流量、真实数据、真实合规下稳定运行"。两者差距必须显式列出：

差距维度POC 状态生产要求
数据规模500 条样本全量 + 实时增量
并发单用户演示峰值 200 QPS（Day2 容量）
合规脱敏数据全流程审计 + 授权链
鲁棒性理想输入脏数据/对抗/长尾

10.2 填补计划

每个差距配"怎么补 + 谁来做 + 多久"：如"并发差距→按 Day2 规划扩到 4 副本，2 周；合规差距→接入审计网关，1 周"。

主动写 POC 差距是"专业度分水岭"。负责人岗的价值之一就是把"演示"和"生产"之间的坑提前暴露并规划，而不是让客户上线后踩雷。这反而增加信任。
POC 差距要诚实列：数据规模、并发、合规、鲁棒性四方面 POC vs 生产的落差，并给"怎么补+谁做+多久"的计划。主动暴露差距反而显专业、增信任，绝不可假装 POC=生产。
① 把 POC 指标直接当生产指标承诺=欺诈风险，面试一追就崩。② 只列差距不给填补计划=甩锅，要体现"我有路径"。③ 差距写"无"=不诚实，任何 POC 都有差距。

十一、成本风险与上线计划（不夸大）

11.1 成本页（呼应 Day2）

  • 用 Day2 的"API vs 私有"交叉点给出成本区间；
  • 标注"估算/示意"，给 sensitivity（量±50% 成本怎么变）；
  • 含安全、运维、知识更新的人力成本。

11.2 风险矩阵

11.3 上线计划

分阶段：试点（单部门）→ 扩面（多部门）→ 生产（全量）；每阶段有成功标准（如试点准确率≥95%）。

成本与风险页是"决策层敢签字"的关键。不夸大、给区间、给缓解，体现你既懂技术也懂兜底。负责人岗要的就是这种"可控感"。
成本页用 Day2 交叉点给区间并标"估算"+sensitivity；风险用矩阵列概率/影响/缓解；上线分试点→扩面→生产并设成功标准。不夸大、给区间、给缓解，决策层才敢签字。
① 成本给单一精确数字（不标估算）会被当成承诺，出错担责。② 风险写"无风险"=不专业。③ 上线计划若无"成功标准"和" rollback 方案"，等于没计划。

十三、面试达标线①：核心结构与叙事逻辑

风险概率影响缓解
知识过时导致答错中高知识更新+回归评测
峰值超容量低中副本扩容+API 兜底
合规审计不通过低高前置安全设计+留痕
要素要能讲清
结构15-18 页骨架：痛点→适用性→数据→四类边界→POC→三作品→架构/安全/评测→部署→NFR→POC差距→成本风险→上线
叙事痛点(量化)→方案(对应作品)→证据(可验证)→诚实成本风险
串联以场景为主线把知识库/Agent/平台串成一套能力
边界规则/RAG/Agent/人工四类各管什么、怎么路由
一句话达标：能默写 15-18 页骨架，讲清"痛点→方案→证据"叙事，用特药理赔场景把三个作品串成闭环，并在方案里画清四类能力边界。这是负责人岗的"方案 owner"视角。

十四、面试达标线②：POC 差距与成本风险诚实写

POC差距 = 数据规模/并发/合规/鲁棒性 四方面 POC vs 生产落差 + 填补计划(怎么补/谁做/多久) 成本风险 = Day2交叉点给区间(标估算+sensitivity) + 风险矩阵(概率/影响/缓解) + 分阶段上线(成功标准) 核心：不夸大、给区间、给路径，主动暴露差距反而增信任
  1. POC 差距：显式列四维度落差，并配填补计划，不假装 POC=生产。
  2. 成本风险：用 Day2 方法给成本区间（标估算），风险用矩阵量化概率/影响/缓解。
  3. 上线计划：分阶段 + 成功标准 + rollback，体现可控。

  • 能讲清"痛点→方案→证据"三段式叙事逻辑及顺序原因。
  • 能默写出 15-18 页标准骨架，并指出四页必保项（痛点/四类边界/POC差距/成本风险）。

  • 痛点页能给出量化指标（工时/错误率/合规），而非定性词。
  • 能讲清规则/RAG/Agent/人工四类边界与"能规则不上RAG、能RAG不上Agent、Agent只编排、风险留人工"原则。
  • 三个作品页都能"回指痛点+给指标+写边界"。
  • 能画出数据架构数据流与存储选型，并列出安全四控制（鉴权/脱敏/最小权限/审计）。

  • 能诚实列出 POC 到生产的四类差距（数据/并发/合规/鲁棒）并配填补计划。

  • 上线计划能分阶段、设成功标准、含 rollback——不夸大、给路径。

十六、高频面试题速记卡

Q：Delivery Pack 和作品集有什么区别？
作品集是可运行的三个作品（证明能力），Pack 是把它们串成"痛点→方案→证据→成本风险"的 15-18 页方案，给决策层看（证明商业理解）。
Q：方案的黄金叙事是什么？
痛点(量化)→方案(对应作品)→证据(可验证)→诚实成本风险。先共鸣问题，再给解法，证据闭环，诚实谈风险反而加分。
Q：18 页骨架里哪四页不能省？
痛点页、四类边界页、POC 差距页、成本风险页——它们是面试官最盯的地方，也是最易暴露专业度的地方。
Q：三个作品怎么串？
以场景为主线：客户问条款→知识库(RAG)，客户审单→Agent(编排)，企业要规模化→平台(治理)。讲"合起来解决一个大问题"，不罗列技术。
Q：四类能力边界怎么分？
规则管确定逻辑、RAG 管知识、Agent 管编排、人工管高风险终判。原则：能规则不上RAG，能RAG不上Agent，Agent只编排，风险必留人工。
Q：POC 差距为什么要诚实写？
POC 是受控小样本，生产是真实流量/数据/合规。主动列差距+填补计划显专业、增信任；假装 POC=生产是欺诈风险，一追就崩。
Q：成本页怎么写才不被当成承诺？
用 Day2 交叉点给区间、标注"估算"、给 sensitivity（量±50%成本怎么变），并含安全/运维/知识更新人力。
Q：上线计划缺什么等于没计划？
缺"成功标准"和"rollback 方案"。必须分阶段（试点→扩面→生产）且每阶段有可量化成功线。
Q：医疗方案安全页为什么不能后置？
合规是一票否决项。要覆盖鉴权、脱敏时机、最小权限、审计留痕，且多租户隔离要讲清实现（如向量库 namespace）。
Q：为什么 LLMOps 页重要？
证明方案"能活下去"——很多 POC 美但上线后指标漂移无人管。要展示评测+监控+回归+知识更新闭环。
