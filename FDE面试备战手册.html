四、面试故事模板（三个，背熟）

故事 1：数据治理 → RAG 不会做成垃圾

"我之前做数仓的时候，处理过企业几十个系统的数据集成，知道数据质量问题是 AI 落地最大的坑。很多人做 RAG 只管把文档扔进向量库，但我知道企业文档是脏的、重复的、版本混乱的。所以我会先做数据治理——去重、版本化、权限分层——再建索引。这是我跟纯应用工程师的差别。"

故事 2：Java 架构 → AI 能力工程化

"我做过 Java 后端架构，知道怎么把一个新能力稳定地接进现有系统。大模型 demo 好做，但上生产要处理流式输出、超时重试、token 限流、多模型路由、灰度发布——这些都是工程问题，不是算法问题，正好是我擅长的。"

故事 3：SQL 建模 → Text2SQL 天然优势

"Text2SQL 的难点不是调模型，是企业表结构乱、指标口径不一致、SQL 写法不规范。我做了多年数仓建模，知道企业真实的 schema 长什么样、join 路径怎么走、聚合口径怎么定义。所以我能把 Text2SQL 从 demo 准确率做到生产可用。"

五、模拟面试题（双线各 10 题，带答题要点）

路线 AText2SQL 方向

Q1. Text2SQL 的核心难点是什么？为什么直接调 GPT-4 准确率上不去？
① Schema 复杂：企业几十上百张表，模型看不全 → 需要 schema linking
② 口径不一致：同名指标在不同部门定义不同 → 需要 schema 治理 + 上下文约束
③ SQL 写法不唯一：模型生成的 SQL 语法对但语义错 → 需要 few-shot 示范
④ 多表 join 路径：模型不知道业务 join 逻辑 → 需要外键关系图 + 路径压缩
Q2. 如果企业的 schema 有 200 张表，怎么让模型生成准确 SQL？
① Schema linking：先用 embedding 检索跟问题相关的表/列，只把相关 schema 喂给模型
② 表结构压缩：去掉无关列，加列注释和示例值
③ few-shot 示例库：维护历史 SQL 示例，按相似度检索 top-k 注入 prompt
④ CoT 推理：让模型先输出"要用哪些表、怎么 join"，再写 SQL
⑤ 执行验证 + 自我修正：执行 SQL，报错则让模型重写
Q3. 怎么评测 Text2SQL 系统的好坏？
① Execution Accuracy（EX）：执行生成的 SQL，结果跟 ground truth 一致即对（比字符串比对更准）
② Valid Efficiency Score（VES）：执行正确 + 执行效率
③ 公开数据集：Spider（跨域）、BIRD（真实脏数据）、WikiSQL（简单）
④ 自建评测集：从企业真实查询日志抽样 + 人工标注
Q4. 用户问"上个月销售额"，模型把"销售额"理解错了，怎么排查？
① 查 schema 注释：列注释是否清楚定义"销售额"口径
② 查 few-shot：是否有类似指标的 SQL 示例
③ 查指标字典：是否维护了指标→列的映射表
④ 改造：加指标元数据层，prompt 里注入"销售额 = SUM(订单金额) WHERE 状态=已支付"
Q5. 用户问题很模糊（"看看数据怎么样"），怎么处理？
① 意图澄清：让 Agent 反问用户"您想看哪个指标？时间范围？维度？"
② 推荐可视化：根据高频查询推荐几个候选分析
③ 多轮对话：维护对话状态，逐步收敛到具体 SQL
Q6. 多表 join 时模型选错 join 路径，怎么解？
① 维护外键关系图，prompt 里只给合法 join 路径
② 路径压缩：预计算常用 join 视图，模型直接查视图
③ few-shot 里放典型 join 示例
Q7. 怎么处理 SQL 注入风险？
① 永远用参数化执行，不要字符串拼接
② 限制只读权限（SELECT only）
③ 加行级权限（RLS），按用户身份过滤
④ SQL 执行前做白名单校验（只允许查特定 schema）
Q8. 用户问题涉及实时数据（"现在库存"），怎么办？
① 区分分析型 vs 实时型查询，路由到不同数据源（数仓 vs 业务库）
② 实时查询走 Flink CDC / 业务库直查，带缓存
③ 加超时 + 降级策略
Q9. 模型生成的 SQL 执行报错，怎么自动修复？
① 捕获错误信息 + 原 SQL，喂回模型让它重写
② 限制重试次数（2-3 次），避免死循环
③ 记录失败 case，回流到评测集持续改进
Q10. 你怎么把 Text2SQL 从 demo 做到生产？
① 数据层：schema 治理、指标字典、few-shot 示例库
② 检索层：schema linking 向量化、SQL 示例检索
③ 生成层：CoT prompt、多模型路由（简单走小模型，复杂走大模型）
④ 验证层：执行验证 + 自我修正 + 人工兜底
⑤ 工程层：限流、超时、缓存、灰度、监控、评测回流

路线 BRAG 方向

Q11. 讲一下 RAG 的完整流程？
离线：文档摄取 → 清洗 → chunk 切分 → embedding → 入向量库
在线：用户 query → query 改写 → embedding → 向量检索（+ BM25 混合）→ rerank → 拼 prompt → LLM 生成 → 引用溯源
Q12. chunk 切分有哪些策略？怎么选？
① 固定长度：简单但可能切断语义
② 按段落/标题：保留结构，适合结构化文档
③ 滑动窗口：相邻 chunk 有重叠，避免边界丢失
④ 语义切分：用 embedding 相似度判断切点
⑤ 经验：先用按标题+滑动窗口 200-500 token，再用 RAGAS 评测调优
Q13. 检索召回率低，怎么优化？
① 混合检索：BM25（关键词）+ 向量（语义）+ RRF 融合
② query 改写：HyDE（先让模型生成假设答案再检索）、query 扩展、多 query
③ rerank：召回 top-50 → cross-encoder rerank 到 top-5
④ embedding 模型：换更强的（bge-large、GTE）
⑤ chunk 优化：太长太短都不行，需调参
Q14. 怎么防止模型"胡说八道"（幻觉）？
① 拒答策略：检索相似度低于阈值则拒答
② 引用溯源：每个回答必须标注来源 chunk
③ prompt 约束："只能基于提供的上下文回答，不确定就说不知道"
④ rerank 提高精度：喂给模型的上下文要准
⑤ 后置校验：用另一个模型验证回答是否在上下文中
Q15. 企业知识库文档很乱（PDF/Word/扫描件/图片混合），怎么摄取？
① 多模态解析：PDF 用 PyMuPDF/unstructured，扫描件走 OCR（PaddleOCR），图片用 VLM
② 表格结构识别：用 Table Transformer 保留表格语义
③ ETL 思维：像我做数仓一样，建摄取→清洗→结构化→入库 pipeline
④ 元数据：每个 chunk 带来源、版本、权限标签
Q16. 文档有权限（销售看销售文档，HR 看 HR 文档），RAG 怎么做权限控制？
① chunk 级权限标签：入向量库时打上部门/角色标签
② 检索时过滤：用 metadata filter 只检索用户有权限的 chunk
③ Milvus 支持标量过滤，可直接用
④ 不要在生成时过滤——会泄露
Q17. RAGAS 评测怎么用？
四个核心指标：
① Faithfulness：回答是否忠于上下文（防幻觉）
② Answer Relevancy：回答是否切题
③ Context Precision：检索的上下文是否相关
④ Context Recall：是否检索全了
用法：构造问答对 + 标准答案，跑 RAGAS 自动评测，持续迭代
Q18. 多文档跨文档问答（"对比 A 产品和 B 产品的差异"），怎么实现？
① 多 query 检索：把一个问题拆成"A 产品特点"和"B 产品特点"两个 query
② 文档聚类：按产品/主题分库，分别检索
③ 长上下文模型：把多文档拼一起喂给长上下文模型（Claude 200k）
④ Map-Reduce：每文档单独总结，再合并
Q19. 知识库经常更新，怎么保证检索实时性？
① 增量索引：文档更新触发重新 embedding，只更新变化的 chunk
② 版本管理：chunk 带版本号，旧版本软删除
③ 缓存失效：相关 query 的回答缓存失效
④ 像我做 ETL 一样，搭定时/触发式摄取 pipeline
Q20. 你之前做过大数据，对 RAG 有什么帮助？
送分题，背故事 1。
① 数据摄取 ETL：文档摄取 = 数据集成，我做过企业级
② 数据治理：去重、版本、权限分层，数仓经验直接用
③ 数据质量：知道脏数据怎么影响下游，会先治理再建索引
④ 工程化：大规模摄取 pipeline、调度、监控，都是我熟悉的
