FDE W8D7 学习手册 · 作品整合与集中投递

W8 Day7 · A 级（高级/架构/负责人岗必考）· 5h · 学完能把三个作品串成完整能力证明，并讲清第 8 周集中投递的策略与优先级

本日定位：W8 收官日。前 6 天你已具备 RAG/Agent/平台/评测/成本安全/负责人视角全套能力，D7 把它们收口成"求职武器"：三个作品怎么整合展示、第 8 周怎么集中投递高薪岗。这是从"会做"到"能拿到offer"的关键一跃。
候选人背景：36 岁，Java + 大数据 + 医疗保险理赔，冲刺高级工程师 / 架构师 / 技术负责人。你的卖点不是"年轻"，而是"从数据到平台都自己建过"的完整能力证据链。
学完能回答：① 三个作品（知识库/Agent/平台）怎么整合、能力如何递进；② 第 8 周集中投递高薪岗的策略与优先级、为什么暂缓某些岗；③ 用 YOYO + 知识库 + Agent + 平台串成差异化面试故事。
使用方法：通读 → 重点看「面试话术」「易错点」→ 用 s11 打磨你的 1 分钟叙事 → 配合《FDE-W8D7-评测题.md》。选中不熟的词可标注（左下★重要 / 右下📌待查）。

一、三个作品概览：知识库 / Agent / 平台

1.1 原理：作品要覆盖"能力光谱"

面试作品不是越多越好，而是要覆盖从底层数据到上层平台的完整能力光谱，让面试官看到"你能独立扛起一条 AI 落地链路"：

作品层级核心证明的能力
企业知识库数据层知识治理、检索、RAG 底座（大数据背景）
特药理赔 Agent应用层场景落地、Agent 编排、合规与 ROI（医疗+AI）
企业 Agent 平台平台层架构设计、能力复用、工程标准（Java+架构）

1.2 为什么是这三个

  • 单独一个只能证明"点"，三个组合证明"面"和"体"。
  • 正好对应你"数据 → 应用 → 平台"的能力成长，不是拼凑。
  • 每个都能讲清"技术决策 + 业务结果 + 沉淀标准"（呼应 W8D6）。
面试官看作品最怕"堆砌"。三个作品必须有一条主线把它们串起来——你是在展示"一个能从数据建到平台的人"，而不是"做了三件不相干的事"。
三作品覆盖数据层(知识库)、应用层(理赔Agent)、平台层(平台)，构成从底层到上层的完整能力光谱。单独一个只证明点，组合才证明"我能独立扛一条 AI 落地链路"。
① 作品不是越多越好，三个没主线比一个精深更糟。② 别把一个大项目拆成三个充数，面试官一深挖就穿。③ 每个作品都要能讲"决策/结果/标准"，只讲技术实现没竞争力。

二、能力递进关系：从数据到平台

2.1 原理：递进 = 难度与抽象层级上升

知识库（让数据可被消费） → 理赔Agent（让 AI 解决具体问题） → 平台（让能力可被复用）

这是一个抽象层级逐级升高、复用价值逐级放大的递进：

层级解决的问题复用范围
知识库知识散乱、检索慢、易错单业务线内
理赔 Agent人工初审慢、差错高单场景
平台每个业务都要重造轮子跨业务线

2.2 递进的"杠杆效应"

知识库是地基，Agent 是上面盖的楼，平台是把"盖楼方法"产品化让所有人能盖。越往上，单位投入撬动的业务价值越大——这正是负责人价值的体现（呼应 W8D6）。

递进是抽象层级升高、复用范围放大：知识库解决"数据可被消费"(单业务线)→Agent 解决"具体问题"(单场景)→平台解决"重复造轮子"(跨业务线)。越往上杠杆越大，体现负责人价值。
① 说"递进"却讲不清为什么后一个比前一个难/值钱，等于没递进。② 把平台说成"只是把 Agent 包了层 API"，低估了平台工程（多租户/监控/标准）的难度。③ 递进要真实，不能硬编"平台是 Agent 自然演化"。

三、作品一：企业知识库（数据层能力）

3.1 原理：RAG 的底座是"好知识库"

知识库解决医疗理赔场景"知识散、更新慢、检索不准"的痛点。你做的核心工作：

  • 知识治理：把保单条款、药品目录、医保政策结构化、版本化（大数据 ETL 能力）。
  • 切分与向量化：按语义切分，兼顾召回精度与上下文完整。
  • 检索优化：混合检索（向量+关键词）+ 重排，提升命中。
  • 更新机制：政策/药品变更触发重建 + 回归评测（呼应 W8D5 数据漂移）。
一句话成果："把 10 年散落的理赔知识变成可秒级检索的资产，支撑了后续所有 AI 应用，检索准确率从 X 提升到 Y。"
知识库是"数据层能力"的证明，正好发挥你大数据背景。面试别只讲向量库，要讲"怎么治理、怎么保证知识新鲜、怎么评测检索质量"——这才是工程深度。
知识库 = 知识治理(结构化版本化) + 切分向量化 + 混合检索重排 + 更新回归。证明数据层能力，亮点是大数据治理与"知识新鲜度"机制，而非单纯接个向量库。
① 只接个向量库就说"做了知识库"，被问切分策略/更新机制就露怯。② 不提知识更新与回归，等于埋了 W8D5 说的"知识过期致答错"的雷。③ 检索只靠向量易漏关键词，要混合检索。

四、作品二：特药理赔 Agent（应用层能力）

4.1 原理：Agent 把"知识"变成"行动"

在知识库之上，特药理赔 Agent 解决"初审慢、差错高"：

  • 多步编排：材料识别 → 政策匹配 → 金额核算 → 风险标记 → 人工终审。
  • 工具调用：调理赔系统、药品库、规则引擎（确定性计算用规则，呼应 W8D5 边界）。
  • 合规与降级：PII 脱敏、置信度低转人工（呼应 W6/W8D5）。
  • 评测与 ROI：建评测集、算初审时效与成本下降（呼应 W8D5）。
一句话成果："特药理赔初审从 2 小时压到 8 分钟，初审员人均日处理量翻 3 倍，材料不全退件率降 40%，释放 5 个初审人力。"
理赔 Agent 是"应用层能力"的证明——把 AI 能力落到真实业务并产生结果。面试要突出"场景选择 + 边界划分 + 合规兜底 + ROI 证明"四件套，这正是高级岗看重的。
理赔Agent = 多步编排(识别→匹配→核算→风险→终审) + 工具调用(规则算确定项) + 合规降级(脱敏/转人工) + 评测ROI。证明应用层落地力，亮点是场景/边界/合规/ROI 四件套。
① 把 Agent 讲成"自动赔付"，踩 W8D5 红线（最终赔付必须由人定）。② 不提评测与 ROI，作品就缺"价值证明"。③ 工具调用不隔离确定性计算，模型算金额易错。

五、作品三：企业 Agent 平台（平台层能力）

5.1 原理：平台把"一次性能力"变成"可复用能力"

当多个业务线都要 Agent，重复造轮子。平台做的事：

  • 统一编排：可视化/配置化 Agent 流程，业务自助搭建。
  • 多租户与安全：租户隔离、PII 治理、审计（呼应 W6/W8D5）。
  • 可观测：统一监控/成本/评测看板。
  • 工程标准：内置提示词版本、降级模板、上线门禁（呼应 W8D6）。
一句话成果："把 Agent 平均搭建周期从 3 周压到 3 天，已支撑 N 条业务线，单位请求成本因复用下降 X%。"
平台是"平台层能力"的证明，发挥你 Java+架构背景。面试要讲清"为什么自研而非 SaaS"（W8D6）、"多租户怎么隔离"、"怎么让能力可复制"——这是技术负责人最硬的证据。
平台 = 统一编排(配置化搭建) + 多租户安全(隔离/PII/审计) + 可观测(监控成本评测) + 工程标准(提示词版本/降级/门禁)。证明平台层能力，亮点是自研决策、多租户、能力复用。
① 把平台说成"只是封装了几个 API"，低估多租户/可观测/标准的工程量。② 不解释"为什么自研 vs SaaS"，架构决策说不清。③ 平台没内置降级与门禁，业务线接了也敢乱上。

六、YOYO + 知识库 + Agent + 平台 串成差异化故事

6.1 原理：用一条主线把作品变成"人物弧光"

单纯罗列作品是"清单"，用主线串联才是"故事"。推荐主线：

从"让知识可用"(知识库) → "让知识解决业务"(理赔Agent) → "让能力可复制"(平台) = 一条"从数据到平台"的能力成长线

其中 YOYO（你的差异化方法论/品牌，可理解为"你的一套 AI 落地打法"）是贯穿三者的"灵魂"：

  • YOYO 之"治理优先"：知识库阶段建立的数据治理标准，贯穿到平台。
  • YOYO 之"场景为王"：理赔 Agent 阶段验证的"选对场景+控边界+证明 ROI"。
  • YOYO 之"能力复用"：平台阶段把前两者沉淀为可复制标准。
故事主线：知识库(让知识可用)→理赔Agent(让知识解决业务)→平台(让能力可复制)，用 YOYO 方法论（治理优先/场景为王/能力复用）贯穿。三个作品不再是清单，而是一条"从数据到平台"的能力弧光。
① YOYO 若只是个空 acronym，被追问"具体指什么"就塌。要让它对应真实可讲的方法。② 故事没有"为什么是你"的差异化，和平凡候选人没区别。③ 主线断裂（平台突然冒出来），递进不成立。

七、第 8 周集中投递策略

7.1 原理：集中投递 = 用"海浪效应"提高命中

分散投递容易"石沉大海"，集中在一周高密集度投递，能：

  • 形成势能：面试邀约集中，便于横向比较 offer。
  • 避免空窗：流程并行，缩短求职周期。
  • 快速迭代：前几场面试暴露的问题，后面场立马改。

7.2 投递节奏

天数动作
Day1-2第一优先岗海投（AI FDE/解决方案架构师）
Day3-4第二优先岗（应用技术负责人）+ 内推同步启动
Day5-7复盘前几场、补叙事漏洞，跟进面试、暂缓岗一律不投
集中投递不是"乱投"，是"有优先级地饱和覆盖"。36 岁候选人的时间贵，要把弹药打在命中率最高的靶上（第一/第二优先），而非广撒网。
集中投递用海浪效应：势能集中、避免空窗、快速迭代。节奏：前2天打第一优先、3-4天第二优先+内推、5-7天复盘补叙事。不是乱投，是有优先级饱和覆盖。
① "集中"变"海投一切"，包括暂缓岗，浪费弹药还稀释定位。② 不内推只网申，命中率天然低。③ 投完不复盘，同样的坑每场都摔。

八、第一优先：AI FDE / 解决方案架构师

8.1 原理：最匹配你的"能力证据链"

AI FDE（现场交付工程师）/ 解决方案架构师，核心是把 AI 技术"对准业务场景交付"，正好吃你的三作品：

岗位要求你的对应作品
懂 RAG/知识库企业知识库
能做场景落地特药理赔 Agent
能画架构/对客户企业 Agent 平台
能证明价值W8D5 的 ROI/价值证明

8.2 投递话术重点

  • 强调"从数据治理到平台交付"的端到端经验。
  • 用医疗理赔的真实结果数字（时效/成本/准确率）。
  • 突出"既懂技术又懂业务"，这是 FDE/架构师最稀缺的。
第一优先 = AI FDE/解决方案架构师，最吃你的三作品+ROI能力。话术重点：端到端(数据→平台)、真实业务数字、技术+业务双懂的稀缺性。
① 投 FDE 却只讲技术不讲客户/业务对齐，不匹配岗位。② 没有真实业务数字，FDE 岗位最看重"交付结果"。③ 把 FDE 当成"纯实施"，忽略方案设计能力要求。

九、第二优先：应用技术负责人

9.1 原理：退可守的"稳岗"

若 FDE/架构师竞争烈，应用技术负责人是强备选——它看重"带人+架构+落地"，你的 Java+大数据+三作品完全够：

  • 带团队：W8D6 的人才结构与带人方法。
  • 架构设计：平台作品 + 自研/SaaS 决策。
  • 业务落地：理赔 Agent 的真实交付。
定位贴士：应用技术负责人岗更看重"稳"，讲"我怎么让团队持续交付、怎么控风险"比讲"我多前沿"更有效。
第二优先 = 应用技术负责人，看重带人+架构+落地。你的 Java+大数据+三作品够打，话术讲"持续交付与控风险"而非贪新，定位更稳。
① 投负责人岗却只讲个人贡献不讲带人，不匹配。② 把"应用技术负责人"当成"低一档随便投"，准备不足易翻。③ 过度强调前沿 AI 忽略"稳交付"，与负责人岗调性不符。

十、暂缓：纯 Agent 开发 / 强出差

10.1 原理：暂缓 ≠ 不能做，是"性价比/定位不符"

暂缓岗暂缓理由
纯 Agent 开发偏执行层、难发挥你的"数据→平台"全栈与领导力，薪资与成长天花板低
强出差交付36 岁家庭/精力约束，且弱化你"建体系"的差异化优势

10.2 但保留"窗口"

  • 若第一/第二优先暂无进展，可把纯 Agent 岗作为"保底面试练手"，不当主目标。
  • 强出差岗若薪资显著溢价且短期，可个案评估，但不作为主线。
暂缓 = 纯Agent开发(偏执行、难发挥全栈领导力、天花板低) 和 强出差(精力约束、弱化建体系优势)。是性价比/定位不符，非不能做；可作保底练手不当主线。
① "暂缓"被理解成"完全不投"，可能错失保底机会与练手场。② 因暂缓而排斥所有 Agent 相关岗，一刀切。③ 强出差岗若薪资溢价巨大仍死守"暂缓"，错过现实选择。

十一、面试叙事：差异化故事怎么讲

11.1 原理：1 分钟讲清"你是谁、你证明了什么"

准备一段1 分钟电梯演讲，结构：背景 → 三个作品递进 → 差异化 → 目标岗。

模板："我是 36 岁的 X，Java+大数据+医疗理赔背景。过去几年我围绕企业 AI 落地建了三件事：先把散落的理赔知识建成可检索的知识库（数据层），再做特药理赔 Agent 把初审从 2 小时压到 8 分钟（应用层），最后沉淀成企业 Agent 平台让搭建周期从 3 周降到 3 天（平台层）。我的差异点是'既懂医疗业务、又能从数据一路建到平台'，所以我想找 AI FDE / 解决方案架构师这样需要对齐业务又端到端交付的岗。"

11.2 叙事三忌

  • 忌流水账（"我做了 A 又做了 B"）。
  • 忌没数字（"效果不错"）。
  • 忌无差异化（"我也用 RAG/Agent"——谁都会）。
差异化是你最大的议价权。36 岁拼不过 25 岁的手速，但能拼"业务深度 + 全栈落地 + 领导力"。叙事要把这三点焊死在面试官脑子里。
1分钟电梯演讲：背景→三作品递进(数据→应用→平台)→差异化(业务深+全栈+领导力)→目标岗。三忌：流水账、没数字、无差异化。差异化是36岁最大议价权。
① 电梯演讲超时（讲 5 分钟），面试官耐心耗尽。② 差异化讲成"我什么都会"，反而显浮。③ 不针对岗位调整叙事，对 FDE 讲一堆管理，对负责人讲一堆模型。

十三、面试达标线①：能讲清三个作品怎么串成完整能力证明

作品层级证明的能力串接逻辑
知识库数据治理/检索/RAG底座地基：让知识可用
理赔 Agent应用场景落地/合规/ROI楼上：让知识解决业务
平台平台架构/复用/标准方法化：让能力可复制
核心叙事：三作品不是孤立清单，而是"数据→应用→平台"的递进能力证据链，用 YOYO 方法论(治理优先/场景为王/能力复用)贯穿，证明"一个能从数据建到平台的人"。每个作品讲清决策/结果/沉淀的标准。

十四、面试达标线②：能讲清第 8 周集中投递的策略和优先级、为什么暂缓某些岗

第一优先(AI FDE/解决方案架构师) → 第二优先(应用技术负责人) → 暂缓(纯Agent开发/强出差)
  1. 第一优先：最匹配"数据→平台"能力链 + ROI 证明，命中率最高。
  2. 第二优先：稳岗备选，看重带人+架构+落地，你的背景够。
  3. 暂缓：纯 Agent 开发（偏执行、难发挥领导力、天花板低）、强出差（精力/差异化弱化）；可保底练手不当主线。
  4. 集中节奏：前 2 天第一优先、3-4 天第二优先+内推、5-7 天复盘补叙事。
策略：第一优先(AI FDE/架构师)饱和覆盖→第二优先(应用技术负责人)稳岗→暂缓(纯Agent/强出差)因性价比或定位不符，仅作保底练手。集中周用海浪效应提高命中、快速迭代。

十五、W8D7 自测清单

  • 能一句话说清三个作品各自在哪一层（数据/应用/平台）证明什么能力。
  • 能画出"知识库→理赔Agent→平台"的递进关系，并解释抽象层级与复用范围如何升高。
  • 能讲清知识库作品的核心工作（治理/切分/混合检索/更新回归），而非只说"接了向量库"。
  • 能讲清理赔 Agent 的"场景/边界/合规/ROI"四件套，并守住"最终赔付由人定"的红线。
  • 能讲清平台作品的"多租户/可观测/工程标准"，并解释为什么自研而非 SaaS。
  • 能用 YOYO 方法论（治理优先/场景为王/能力复用）把三作品串成一条主线故事。
  • 能解释"集中投递"的海浪效应与节奏安排（前2天/3-4天/5-7天）。
  • 能说清第一优先（AI FDE/解决方案架构师）为什么最匹配你的能力链。
  • 能说清第二优先（应用技术负责人）的话术重点（稳交付/控风险）。
  • 能说清暂缓岗（纯 Agent 开发/强出差）的理由，以及"暂缓≠不投保底"的窗口。

十六、高频面试题速记卡

Q：你三个作品之间有什么关系？
递进不是拼凑：知识库(数据层,让知识可用)→理赔Agent(应用层,让知识解决业务)→平台(平台层,让能力可复制)。抽象层级与复用范围逐级升高。
Q：知识库作品你做了啥深度的？
不止接向量库：知识治理(结构化版本化)+语义切分+混合检索重排+更新触发重建与回归评测。亮点是大数据治理与知识新鲜度。
Q：理赔 Agent 最终能自动赔付吗？
不能。AI 做初筛+建议，最终赔付由人定（W8D5 红线）。作品讲的是初审时效降93%、释放人力，不是"全自动赔"。
Q：平台为什么自研不买 SaaS？
核心差异化+强合规(数据不出域)+长期复用摊薄成本。底座用框架、行业know-how自研，非核心才考虑SaaS验证。
Q：YOYO 是什么，怎么串故事？
贯穿三作品的差异化方法论：治理优先(知识库)→场景为王(理赔Agent)→能力复用(平台)。让作品从清单变成"从数据到平台"的弧光。
Q：为什么要"集中"投递而不是慢慢投？
海浪效应：势能集中便于横向比offer、避免空窗、前几场暴露的问题后面立马改。但集中=有优先级饱和覆盖，不是海投一切。
Q：第一优先为什么是 AI FDE/架构师？
最吃你的"数据→平台"能力链+ROI证明，且看重"既懂技术又懂业务"的稀缺性。话术重点端到端经验+真实业务数字。
Q：为什么暂缓纯 Agent 开发岗？
偏执行层，难发挥你全栈落地与领导力，薪资与成长天花板低。可当保底练手，不当主目标。
Q：36 岁怎么讲差异化不显老？
拼业务深度+全栈落地+领导力，不拼手速。电梯演讲焊死"既懂医疗业务、又能从数据建到平台"。
Q：1 分钟电梯演讲怎么不翻车？
结构：背景→三作品递进→差异化→目标岗。三忌：流水账、没数字、无差异化。超时/讲成"我什么都会"都减分。
