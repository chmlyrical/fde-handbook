一、技术负责人的角色定位：不只是写代码

1.1 原理：从"个人贡献者"到"杠杆者"

高级工程师靠"自己写"产出，技术负责人靠"定方向 + 建机制 + 带人"放大团队产出。AI 项目里这个区别更明显——模型能力趋同，能把 AI 用对场景、带团队持续交付、对结果负责的人稀缺。

维度高级工程师技术负责人
产出方式自己写代码/方案通过团队产出，定标准与架构
关注点技术正确性技术正确性 + 业务结果 + 人
责任边界模块/任务项目成败、质量、风险、团队成长
AI 项目调得动模型、写得通链路选得对场景、建得起能力、扛得住决策

1.2 技术负责人的三个核心动作

  1. 定标准：工程规范、评测规范、AI 安全红线。
  2. 带人：招对人、培养人、分配合适的事。
  3. 扛责：技术选型拍板、上线决策、出事兜底。
面试里被问"你和技术骨干有什么区别"，别答"我管人"——要答"我负责把不确定变成确定：定标准让团队不踩坑、带人让能力可复制、扛责让业务敢用"。这才是负责人价值。
技术负责人 = 定标准 + 带人 + 扛责，不是"写更多代码"。AI 项目里负责"选对场景、建起能力、拍板决策、对结果负责"，靠杠杆放大团队产出，而非个人手速。
① "负责人就是分配任务"是误解——真正的负责人是"最难的判断我来定、最坏的结果我兜"。② 不要贬低写代码，负责人也要保持技术判断力，否则拍板会变成瞎拍。③ 讲角色时别只说"管理"，要落到"技术领导力"具体动作。

二、带团队建设企业 AI 能力：人才结构

2.1 原理：AI 工程团队是"混编部队"

企业 AI 能力不是单一角色能建起来的，需要多种能力互补。结合你的医疗+Java 背景，可设计这样的结构：

角色职责你的匹配度
AI 应用工程师RAG/Agent 链路、提示词、评测可主导（你已掌握全套）
后端/平台工程师服务化、API、多租户、监控你的 Java 强项
数据工程师知识库构建、ETL、数据治理你的大数据强项
算法/微调工程师Fine-tune、模型选型可协作（W7 已懂边界）
业务/领域专家理赔规则、合规、验收你的医疗背景是桥梁

2.2 带人的关键

  • 招"互补"不招"克隆"：团队要有算法+工程+业务的多样性。
  • 建立成长机制：用评测集、复盘会、技术分享让新人快速长出手感。
  • 授权 + 兜底：给成员 ownership，但关键决策负责人拍板。
你能把"医疗领域知识 + Java 工程 + 大数据治理 + AI 应用"串成团队能力图，这本身就是负责人视角的体现。面试要展现"我知道一个 AI 项目需要哪些人、各自干什么、我补哪块"。
企业 AI 团队是混编：AI 应用 + 后端平台 + 数据 + 算法 + 业务专家。负责人要招互补而非克隆、建成长机制、授权且兜底。你的 Java+大数据+医疗恰好覆盖工程/数据/业务三块，是天然桥梁。
① 不要以为"招个算法大牛就万事大吉"——算法落不了地，缺工程和业务一样崩。② 负责人自己不写代码但也不懂技术，会变成"传声筒"，失去拍板资格。③ 团队能力要"可复制"，不能只在你一个人脑子里。

三、技术选型决策框架

3.1 原理：选型 = 在约束下做权衡

技术负责人每天做选型，核心不是"哪个最先进"，而是"哪个在当前约束下最合适"。约束包括：团队能力、时间、成本、合规、可维护性。

选型决策 = f(需求匹配度, 团队熟悉度, 成本, 合规, 长期可维护, 风险)

3.2 决策清单

问题引导思考
团队会不会用？选陌生技术要算学习成本与踩坑风险
能扛合规吗？医疗数据是否允许出域（呼应 W6/W8D5）
长期谁维护？避免"只有一个人懂"的孤儿技术
能退能换吗？是否锁死供应商、有无抽象层
选型要"可解释、可回滚"。面试里被问"为什么选 Qwen/DeepSeek 而不是 GPT"，要回到约束：合规不出域、成本、中文医疗场景表现、私有化可行——而不是"因为火"。
选型不是在"最先进"里挑，而是在约束（团队/时间/成本/合规/可维护）下权衡。决策要可解释、可回滚、不被供应商锁死。医疗场景优先合规不出域与中文表现。
① "别人用我就用"是甩锅式选型，出事没人扛。② 过度追求"不锁定"导致自研一切，反而拖慢且易烂尾。③ 选型文档不写"为什么不选别的"，半年后团队忘了初衷，白交学费。

四、跨团队协调：AI 项目里的协作

4.1 原理：AI 项目是"跨职能"的，负责人是枢纽

AI 落地要拉通业务、数据、算法、工程、合规、运维。负责人要当"翻译器"和"推动器"：

  • 对业务：把需求翻译成可落地的 AI 场景与验收标准（呼应 W8D5 价值翻译）。
  • 对数据：推动知识库建设、数据治理口径对齐。
  • 对合规：提前介入，别等上线被审计卡。
  • 对运维：把监控/成本/SLA 要求前置。

4.2 协调三原则

  1. 目标对齐：各方对"成功"定义一致（用门禁指标，见 W8D5）。
  2. 节奏同频：固定同步会 + 共享看板，避免信息孤岛。
  3. 责任到岗：RACI 明确谁负责、谁审批。
协调能力是负责人岗的分水岭。能讲出"我怎么推动业务给标注、推动合规提前评审、推动数据团队建知识库"的具体故事，比讲技术更体现负责人成色。
AI 项目跨业务/数据/算法/工程/合规/运维，负责人是枢纽+翻译器。原则：目标对齐（共定门禁）、节奏同频（看板同步）、责任到岗（RACI）。提前拉合规，别上线被卡。
① 等技术做完才找合规，常被一票否决推倒重来。② 目标没对齐就开干，业务要苹果、你交橘子。③ "大家都负责"=没人负责，RACI 必须落到具体人。

五、架构决策：什么时候自研 / 用框架 / 用 SaaS

5.1 原理：三个选项的成本收益结构不同

选项优势代价适合
自研完全可控、可深度定制成本高、周期长、要养人核心差异化、强合规、长期战略
用框架复用成熟能力、快受框架约束、需学习通用能力（RAG/Agent 编排）
用 SaaS最快、免运维数据出域风险、锁定、贵试水、非核心、量小

5.2 决策启发式

核心且合规敏感 → 自研/私有化框架 ｜ 通用能力 → 框架 ｜ 试水非核心 → SaaS
企业 Agent 平台（你的作品三）是"核心差异化"——适合基于框架自研而非纯 SaaS；而某些非核心的客服 bot 可以用 SaaS 快速验证。负责人要能画出"哪些自研、哪些采购"的边界。
自研=可控但贵慢；框架=复用快但有约束；SaaS=最快但有出域/锁定/成本风险。启发式：核心且合规敏感来自研/私有框架，通用能力用框架，试水非核心用 SaaS。
① "全自研"显实力但常拖死项目，要克制。② "全 SaaS"省事但数据出域+供应商锁定，医疗场景高危。③ 框架选了冷门的，团队招不到人、社区不活跃，长期成孤儿。

六、自研 vs 框架 vs SaaS 的权衡矩阵

6.1 用一张表做决策

评估项自研框架SaaS
上线速度慢中快
可控性高中低
数据合规最好（私有）好（可私有部署）差（出域）
长期成本看规模中随量升
团队要求高中低
供应商风险无低高

6.2 组合策略（推荐）

  • 底座用框架、差异化自研：RAG/Agent 编排用成熟框架，行业 know-how（理赔规则、知识治理）自研封装。
  • 非核心用 SaaS 验证：先 SaaS 跑通 PMF，再视合规/成本决定是否内化。
权衡矩阵看速度/可控/合规/成本/团队/供应商六维。推荐"底座框架 + 差异化自研 + 非核心 SaaS 验证"，而非极端全自研或全 SaaS。
① 不要只看"上线速度"选 SaaS，忽略后续数据出域被合规一票否决。② 自研比例过高，团队被维护拖垮，没精力做业务。③ 没做"内化触发条件"，SaaS 跑顺了也不敢切，长期被绑。

七、定标准：工程标准与评测规范

7.1 原理：标准是"让团队不踩同一个坑"的机制

负责人要把"个人经验"变成"团队规范"。在 AI 项目里尤其要定：

  • 工程标准：提示词版本管理、链路可观测、降级必写、配置外置。
  • 评测规范：评测集怎么建、指标怎么算、回归怎么跑（呼应 W8D5）。
  • 安全红线：PII 处理、租户隔离、越权拒答、人工兜底（呼应 W8D5/W6）。
  • 上线规范：门禁指标、灰度比例、回滚预案。
示例：规定"所有面向用户的 LLM 输出必须带引用溯源 + 可解析结构 + 人工兜底开关"，一条规范就挡住大量幻觉与合规事故。
"定标准"是负责人最被低估的价值。面试能甩出几条你定的团队规范，比讲十个技术点都管用——它证明你能把能力"制度化"。
标准 = 把个人经验变团队规范：工程标准（提示词版本/可观测/降级/配置外置）、评测规范（集怎么建/指标/回归）、安全红线（PII/隔离/拒答/兜底）、上线规范（门禁/灰度/回滚）。
① 定了标准不查执行，等于没定。要有 code review / 评测门禁兜底。② 标准太细太死，团队束手束脚；太粗又防不住坑，要适度。③ 标准不随技术演进更新，很快过时变成负担。

八、扛责：风险 / 质量 / 上线决策

8.1 原理：负责人的"责"是兜底性的

扛责体现在三个时刻：

时刻负责人动作
技术选型拍板并承担后果，不甩给委员会
上线决策看门禁指标 + 降级预案，决定放/不放
出事第一时间兜底、复盘、担责、改进

8.2 质量与风险的平衡

  • 不拿用户赌：没降级预案不放量（呼应 W8D5）。
  • 可接受的不完美：先上"AI 初筛 + 人工终审"，而非等完美再上。
  • 复盘文化：bad case 复盘对事不对人，沉淀为规范。
面试讲"扛责"最好带一个真实（或强可信的）故事：某次上线出问题，你如何第一时间兜底、复盘、把教训变成团队规范。这比空谈"我有责任心"有力十倍。
扛责 = 选型拍板担后果 + 上线看门禁与降级决定放不放 + 出事第一时间兜底复盘改进。质量上不拿用户赌、接受"AI初筛+人终审"的不完美、建对事不对人的复盘文化。
① "集体决策"变"无人决策"，关键时刻要有人拍板。② 出事甩锅给下属/模型，信任瞬间破产。③ 追求"零风险完美再上"，项目永远上不了线，错过窗口。

九、模拟面试准备：用通义 / DeepSeek 当面试官

9.1 原理：面试是"可训练"的技能

很多技术过硬的人面试翻车，是因为表达没结构、叙事没重点。用大模型当面试官可以低成本高频演练。

9.2 操作流程

  1. 设定角色：让通义/DeepSeek 扮演"某大厂 AI 平台技术负责人面试官，严苛、追问细节"。
  2. 喂背景：粘贴你的简历要点（36 岁 / Java+大数据+医疗 / 三个作品）。
  3. 限时口述：用语音或打字在 2-3 分钟内答，逼自己结构化（STAR：情境-任务-行动-结果）。
  4. 要反馈：让面试官给"哪里空泛、哪里缺数字、哪里逻辑断"。
  5. 录音复盘：回听自己的"嗯/啊/绕"，下次砍掉。
提示词模板："你是我应聘的 AI 平台技术负责人面试官。我是 36 岁候选人，背景 Java+大数据+医疗保险理赔，做过企业知识库、特药理赔 Agent、企业 Agent 平台三个作品。请基于我的背景连环追问技术领导力与架构决策，每次只问一题，听我回答后指出不足并追问。"
模拟面试的核心是"暴露表达漏洞"。大模型不会累、不会嫌弃你，是最便宜的陪练。关键是你得真开口练，而不是只看答案。
面试可训练：用通义/DeepSeek 扮严苛面试官，喂背景、限时用 STAR 口述、要反馈、录音复盘。重点暴露"空泛/缺数字/逻辑断"，逼自己结构化表达。
① 只看不算练——不开口永远发现不了"一紧张就跑题"。② 让面试官只给好评会虚假自信，要它"严苛追问"。③ 复盘只听不改，下次照样犯，要逐条改逐条练。

十、一轮完整高级模拟面试（题纲 + 评分）

10.1 题纲（约 45 分钟，6 轮连环追问）

轮面试官问题考察
1"用 3 分钟介绍你最自豪的一个 AI 项目，重点讲你个人的技术领导力。"叙事 + 领导力
2"你选 Qwen/DeepSeek 而非 GPT 的理由？如果合规放开你会换吗？"选型决策
3"特药理赔 Agent 从 POC 到生产，你踩过/会防哪些坑？"落地能力（W8D5）
4"你的企业 Agent 平台为什么自研而不是买 SaaS？边界在哪？"架构决策
5"你怎么向老板证明这个 AI 项目值得继续投钱？"价值/ROI（W8D5）
6"团队里算法和工程吵架，你怎么拍板？出生产事故你第一动作是什么？"扛责 + 协调

10.2 自评分维度（每项 0-5）

  • 结构：回答是否 STAR、有没有结论先行。
  • 数字：是否给出可量化的结果（时效/成本/准确率）。
  • 深度：是否被追问后仍能展开原理与权衡。
  • 领导力：是否体现"定标准/带人/扛责"而非"我一个人写"。
完整一轮：6 轮连环追问覆盖叙事/选型/落地/架构/ROI/扛责。自评看结构(STAR)、数字(量化)、深度(被追问还能展开)、领导力(定标准带人扛责)。
① 第 1 题就讲技术细节忘了讲"我做了什么决策"，面试官抓不到领导力。② 被追问就慌、开始编，不如诚实"这块我后续会补"。③ 全程不提数字，故事没重量。

十一、投递关键词与简历叙事

11.1 原理：关键词决定能不能过简历筛选

你的目标是高级/架构/负责人岗，简历要精准命中的关键词：

岗位方向必含关键词
AI FDE / 解决方案架构师大模型应用、RAG、Agent、Prompt、评测体系、客户方案、PoC 到生产
应用技术负责人技术团队管理、架构设计、Java、微服务、大数据、AI 平台
医疗 AI 方向医疗保险、理赔自动化、知识库、合规(PII/等保)、私有化部署

11.2 叙事策略

  • 用动词开头 + 数字结果：".主导特药理赔 Agent，初审时效降 93%，释放 5 人日/日"。
  • 把三个作品串成能力递进（见 W8D7 s6）。
  • 36 岁要讲"经验红利"：业务理解深、能扛责、沟通成本低，而非和 25 岁拼手速。
投递关键词按岗位方向命中：AI FDE 命中 RAG/Agent/评测/PoC-生产；负责人命中团队管理/架构/Java/大数据；医疗命中理赔自动化/合规/私有化。叙事用动词+数字，讲经验红利。
① 堆砌不相关关键词（如硬写"深度学习 PhD"）被深挖就露馅。② 简历只列技术不列结果，像岗位说明书。③ 36 岁简历还写"热爱学习、能加班"，反而弱化经验优势。

十三、面试达标线①：能讲清技术负责人在 AI 项目里的角色

角色动作具体体现不是什么
定标准工程/评测/安全/上线规范制度化不是"我写文档"
带人招互补、建成长、授权兜底不是"我分配任务"
扛责选型拍板、上线决策、出事兜底不是"我管进度"
核心叙事：技术负责人 = 定标准 + 带人 + 扛责，靠杠杆放大团队产出。在 AI 项目里负责"选对场景、建起能力、拍板决策、对结果负责"，不是"写更多代码"。被问区别时答"我把不确定变成确定"。

十四、面试达标线②：能讲清三个作品体现的技术领导力叙事

知识库(数据层:治理/检索) → 特药理赔Agent(应用层:场景落地) → 企业Agent平台(平台层:能力复用) = 从"数据"到"平台"的领导力递进
  1. 知识库：体现你"把混乱医疗知识变成可检索资产"的数据治理能力（大数据背景）。
  2. 特药理赔 Agent：体现你"选对场景、带落地、控合规与 ROI"的应用领导力（医疗+AI）。
  3. 企业 Agent 平台：体现你"定架构标准、让能力可复制"的平台领导力（Java+架构）。
  4. 串起来：不是三个孤立项目，而是一条"我能从数据一路建到平台"的能力证据链（详见 W8D7）。
叙事：知识库(数据治理)→理赔Agent(场景落地)→Agent平台(能力复用) 构成从数据到平台的递进。每个作品讲清"我做了什么决策、带了什么结果、沉淀了什么标准"，合起来证明技术领导力。

十六、高频面试题速记卡

Q：你和技术骨干有什么区别？
我负责把不确定变确定：定标准让团队不踩坑、带人让能力可复制、扛责让业务敢用。靠杠杆放大团队产出，不止自己写代码。
Q：AI 团队该怎么搭？
混编：AI应用+后端平台+数据+算法+业务专家。招互补不招克隆，建成长机制，授权且兜底。我的Java+大数据+医疗覆盖工程/数据/业务三块。
Q：为什么选 Qwen/DeepSeek 不选 GPT？
约束权衡：合规不出域、中文医疗表现、私有化可行、成本与长期可维护。不是"因为火"，是可解释、可回滚的决策。
Q：自研还是 SaaS？
核心且合规敏感来自研/私有框架，通用能力用框架，试水非核心用SaaS。推荐底座框架+差异化自研+非核心SaaS验证。
Q：技术负责人怎么"定标准"？
把个人经验变团队规范：工程(提示词版本/可观测/降级)、评测(集/指标/回归)、安全(PII/隔离/拒答/兜底)、上线(门禁/灰度/回滚)。
Q：出生产事故你第一动作？
先兜底止损（降级/转人工）→ 定位复盘（对事不对人）→ 沉淀为规范防再犯。不甩锅，担责改进。
Q：怎么用大模型练面试？
扮严苛面试官+喂背景+限时STAR口述+要反馈+录音复盘。关键真开口练，让它不仅给好评而是连环追问。
Q：36 岁怎么讲优势不显老？
讲"经验红利"：业务理解深、能扛责、沟通成本低、定标准带人。用动词+数字讲结果，不拼手速不写"热爱加班"。
Q：三个作品怎么体现领导力？
知识库(数据治理)→理赔Agent(场景落地)→Agent平台(能力复用)，从数据到平台的递进，每个讲清决策/结果/沉淀的标准。
Q：算法和工程吵架你拍板？
回到约束与目标（门禁指标/合规/成本）拍板，不和稀泥。决策可解释、可回滚，并对后果负责。
